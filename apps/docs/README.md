# Documentation

Source for the FlareDispatch site. One Astro build with Starlight serves three things at
<https://flare-dispatch.fractalbox.dev>:

| Path | Content | Source |
| --- | --- | --- |
| `/`, `/roadmap/`, `/benchmarks/` | Product page, roadmap and status, and modeled run costs: plain Astro pages with their own layout and stylesheet. `/` carries no status, which `test/specs.test.ts` checks; `/roadmap/` holds all of it | [`src/pages/`](src/pages/), [`src/data/status.ts`](src/data/status.ts), the phase table of `specs/roadmap.md` read at build time, [`src/data/benchmarks.ts`](src/data/benchmarks.ts) priced through `packages/core/src/cost.ts` |
| `/docs/` | Documentation of what deploys today | [`src/content/docs/docs/`](src/content/docs/docs/), plus the mounted guides, run catalog, action READMEs and reference |
| `/specs/` | Every file under `specs/` | [`specs/`](../../specs/README.md), read in place |

One sidebar and one Pagefind search index cover `/docs/` and `/specs/`. The site also serves
`/llms.txt`, `/llms-full.txt` and `robots.txt`, generated from the same pages in sidebar order.

Two kinds of file under this directory are maintained differently:

- **Guides** are hand-written and reviewed like code: [`substrate/`](substrate/README.md).
- **Reference** is generated by TypeDoc from the package it documents, and committed:
  [`reference/`](reference/substrate-contract/README.md). Never edit a file under `reference/`;
  run `pnpm docs:reference` and commit what it writes. `.github/workflows/docs.yml` regenerates the
  reference on every pull request and fails when the committed output differs, because a
  hand-maintained API reference drifts from the types consumers pin and the drift stays invisible
  until someone follows it into a compile error.

## How a file becomes a page

| Step | Code |
| --- | --- |
| `MOUNTS` maps repository directories to route prefixes. The loader runs Astro's glob loader over each one in place, so the site holds no copy of a file. `specs/spend.md` is `/specs/spend/`, `apps/docs/substrate/facade.md` is `/docs/substrate/facade/`, and a `README.md` is its directory's index. | [`src/lib/pages.mjs`](src/lib/pages.mjs), [`src/content.config.ts`](src/content.config.ts) |
| A repository file has no front matter. The loader takes the page title from the first `# ` heading and the description from the first paragraph, and the page drops that heading from its body. Pages under `/specs/` carry a banner naming them as v2. | `pageFrontmatter` and `repoLinks` in [`src/lib/pages.mjs`](src/lib/pages.mjs) |
| A Markdown plugin points each relative link at the target page's route. A link from a page outside `specs/` to a repository file that is not a page points at GitHub. | `repoLinks` in [`src/lib/pages.mjs`](src/lib/pages.mjs) |
| The Merlion integration renders each ```` ```mermaid ```` block to inline SVG at build time. It supports flowchart, sequence and state diagrams ([`vendor/merlion/`](vendor/merlion/README.md)). `node apps/docs/scripts/check-diagrams.mjs specs/**/*.md` renders every diagram without a full build. | [`astro.config.mjs`](astro.config.mjs) |
| The sidebar has one group per area. The `/docs/` sections are listed in `nav.mjs`. The `/specs/` sections derive from the index table in `specs/README.md` and the ADR files: overview, areas in table order, roadmap, decision records. | [`src/lib/nav.mjs`](src/lib/nav.mjs), `areaFiles` in [`src/lib/specs.mjs`](src/lib/specs.mjs) |
| `public/_redirects` maps older paths to their pages. Workers static assets apply it before asset lookup, so it lists each old specification path and never names a live page. | [`public/_redirects`](public/_redirects) |

To publish a new specification, add the file to `specs/` and a row to the index table in
`specs/README.md`. To publish another `/docs/` page, add the file to `src/content/docs/docs/` or a
mount, and its id to a section in `nav.mjs`.

## What fails the build

| Condition | Where it is checked |
| --- | --- |
| A page belongs to no sidebar section, or a section names a missing page | `sections` in [`src/lib/nav.mjs`](src/lib/nav.mjs), when the config loads |
| A relative link in a specification file leaves `specs/`, is a site path or names a missing file | `linkTarget` in [`src/lib/specs.mjs`](src/lib/specs.mjs), reported by the site check |
| A relative link in another repository page leaves the repository or names a missing file | `pageHref` in [`src/lib/pages.mjs`](src/lib/pages.mjs), reported by the site check |
| A link or anchor in a Markdown page has no target | `starlight-links-validator` |
| A link or anchor in any built HTML page, the product page included, has no target | [`src/lib/site-check.mjs`](src/lib/site-check.mjs), at `astro:build:done` |
| A Mermaid block fails to render, or the rendered diagrams under `/specs/` differ in number from the Mermaid blocks under `specs/` | [`src/lib/site-check.mjs`](src/lib/site-check.mjs) |
| A mounted file or a specification file has no page | [`src/lib/site-check.mjs`](src/lib/site-check.mjs) |

The site check logs the page count and the diagram count of each build.

## Develop and deploy

```sh
pnpm --filter @fractalboxdev/flare-dispatch-docs run dev     # local preview
pnpm --filter @fractalboxdev/flare-dispatch-docs run build   # what CI runs
pnpm --filter @fractalboxdev/flare-dispatch-docs run test    # routes, links, sidebar, redirects
```

`.github/workflows/docs.yml` tests and builds the site on every pull request and deploys it on
`main`, to a static-assets Worker (`wrangler.jsonc`). The dispatcher Worker (API, webhooks,
dashboard, log viewer) serves the custom domain the root `wrangler.jsonc` routes.
