# Native gate leaves retain the comparison scope

**Status:** accepted

## Decision

Authoritative head/base stage discovery supplies the native leaf inventory. Two supported MSVC targets map to the canonical native command owner; unsupported native leaves refuse before fan-out. No dispatcher matrix creates undiscovered checks.

The gate parent joins every discovered nonnative child successfully before native admission. Missing nonnative inventory refuses. Native leaves carry the exact comparison base, gate mode, empty release profile and immutable source identity. They run their canonical leaf command without Linux-specific predecessors; the parent retains those independently executed verdicts.

Only the registered native-gate runtime receives the gate port. Its source identity matches authenticated runtime metadata and decoded comparison input. Release authority is unavailable through this port. The release base-equals-head convention grants no gate comparison scope. Missing native configuration refuses.

Native result admission and reconciliation use the owners named in ADR-0007. A Workflow completion projection remains insufficient; exact controller-verified immutable evidence supplies the native leaf verdict. A failed native child fails the parent. The native owner uses existing child-run admission rather than another provider queue or dispatch client.

## Cost

Native admission follows the complete nonnative wave, so it cannot overlap its prerequisites. Its join budget derives from bounded native execution, admission and finalization budgets. Fixtures bind both native target identities but establish no real MSVC compiler or execution outcome. Deployment of the reviewed executor, installation permission and authentic host receipts remain prerequisites for standing native acceptance.
